# ClassPresenter

Present slides (PDF or PPTX) with a global timer and per-slide timers, alert sounds and background music.

Originally built on Floot; this repo is now standalone and deploys to Vercel.

## Stack
- **Frontend:** Vite + React 19 + React Router (`pages/`, `components/`, `helpers/`)
- **API:** one Vercel serverless function (`api/index.ts`) dispatching to `endpoints/**/*_GET|POST.ts`. `vercel.json` maps `/_api/*` to it.
- **Database:** Neon Postgres (Kysely). Schema in `db/schema.sql`.
- **Files:** Neon Object Storage (S3 compatible) through presigned URLs (`helpers/storage.ts`). Each user has a 1 GB quota.
- **Auth:** email + password (bcrypt, signed session cookie). Optional Google sign-in.

## Environment variables
See `.env.example`. Required: `DATABASE_URL`, `JWT_SECRET`, `AWS_ENDPOINT_URL_S3`, `AWS_REGION`, `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `STORAGE_BUCKET`.

Google sign-in (optional): create an OAuth client in Google Cloud, add the redirect URI `https://<your-domain>/_api/auth/oauth_callback`, then set `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` and `VITE_GOOGLE_AUTH=true`.

## Browser uploads need bucket CORS
Files are uploaded straight from the browser to the bucket. With the Neon bucket created here, cross-origin `PUT`/`GET` from the Vercel domain were observed to be accepted without extra configuration; if you switch storage providers, make sure the bucket allows `PUT`/`GET` from your site origin.

## Develop
```
npm install
npm run dev        # frontend; run `vercel dev` for the API
npm run typecheck
npm run build      # regenerates server/_routes.ts, then builds the frontend
```
`server/_routes.ts` is generated by `scripts/gen-routes.mjs`; re-run it after adding an endpoint.
